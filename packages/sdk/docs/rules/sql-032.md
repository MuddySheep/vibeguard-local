# SQL-032 — EXPLAIN ANALYZE wrapping destructive statement

  | | |
  |---|---|
  | **Severity** | `info` |
  | **Confidence** | 80 |
  | **Threat category** | `destruction` |
  | **Default** | ON |
  | **Stable since** | `1.1.0` (catch ID reserved; detection logic lands in a follow-up v1.1 phase) |

  ## Pattern

  EXPLAIN ANALYZE actually executes its inner statement (it is the only way to gather true runtime stats). Wrapping UPDATE / DELETE / INSERT / DROP / TRUNCATE / ALTER inside EXPLAIN ANALYZE looks like a 'just planning' query but runs the destructive operation in full.

  ## Status

  This catch ID is **reserved** as part of the v1.1 Postgres catalog
  expansion. The forever-stable ID guarantee in
  [STABILITY.md](../../STABILITY.md) applies from the moment this entry
  ships in `RULE_REGISTRY`. Detection logic is being implemented in a
  follow-up v1.1 phase; until then the rule is registered as a no-op
  placeholder so consumers can already key on the ID.
